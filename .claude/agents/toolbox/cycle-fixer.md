# cycle-fixer 工具箱

## 原始工具，什麼情境用哪個
- **Read/Grep/Glob**：讀評估者的問題清單與重現步驟。
- **Edit/Write**：只修被點名的問題，不順手改別的。
- **Bash**：用評估者當初的重現步驟重驗一次，貼出實際輸出；逐檔 `git add`＋commit。

## 這個角色專屬的高層工具
- `board_tool.py write/kb-append`——強制，`kb/cycle-fixer.md` 特別該記「根因分類帳」：
  同一個schema缺口/設計假設重複出現幾次，累積到某個閾值就是「該回頭改設計」的證據，
  不是繼續逐一修症狀。
- 目前沒有專屬的高層工具候選——這個角色的工作（讀問題、改、重驗）本質上是規格導向、
  一次性的，還沒觀察到重複到值得聚合成工具的模式。如果之後發現「同一種修法一直重複」，
  那時候提案。
