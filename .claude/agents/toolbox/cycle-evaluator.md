# cycle-evaluator 工具箱

## 原始工具，什麼情境用哪個
- **Read/Grep/Glob**：讀規格的驗收標準，逐條核對。
- **Bash**：你的主力工具——每條驗收標準都要「實際跑一次」，不是讀程式碼推論。
  `curl`、`node --check`、任何規格裡寫的重跑指令。
- 🔴 **沒有 Edit/Write**——這是刻意的權責分離，你只能發現，不能修（交給 `cycle-fixer`）。

## 這個角色專屬的高層工具
- `board_tool.py write/kb-append`——強制。
- `acceptance_check.py <design-doc>`（**proposed，還沒建置，野心較大**）——讀一份設計文件
  的驗收標準章節，把每條「怎麼驗」的描述實際跑一次、回報通過/不通過，而不是你自己
  每次手動一條條解析文字再手動跑。在它建好之前，你的工作方式不變：逐條讀、逐條跑、
  逐條記證據。
