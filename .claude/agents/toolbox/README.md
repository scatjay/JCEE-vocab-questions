# 工具箱（toolbox/）：每隻代理人自己的，不是共用清單

> `TOOLS.md`（repo 根目錄）是**全隊共用的主登記**——工具有哪些、狀態是什麼、
> 生態治理怎麼跑。`toolbox/<name>.md` 是**這隻代理人自己的**——從主登記裡跟我有關的
> 那幾樣，加上我自己用出來的心得。兩份不是複本關係：主登記負責「這個世界有什麼」，
> 工具箱負責「我怎麼用」。

## 這跟 kb/ 的關係（兩個平行結構，別搞混）

| | 累積什麼 | 檔案 |
|---|---|---|
| `kb/<name>.md` | **判斷力**——這次學到的領域知識、哪個結論被推翻了 | 已存在 |
| `toolbox/<name>.md` | **工具用法**——我會用到哪些工具、什麼情境用哪個、用起來的眉角 | 這份 |

一個是「我懂什麼」，一個是「我會用什麼、怎麼用」。兩者都是**只增不改**，
規則跟 `kb/README.md` 一樣：標日期、被推翻/過時的往下移註記，不刪除。

## 工具箱裡該有什麼

1. **原始工具，但寫成「什麼情境用」不是「有哪些」**（frontmatter 的 `tools:` 已經寫了
   有哪些，工具箱不重複那份清單，只寫**這個角色典型會在什麼情境動用哪一個**）。
2. **這個角色專屬的高層工具**（`TOOLS.md` 第二層裡跟這個角色有關的那幾支，含還在
   `proposed` 階段、我可能會用到的）。
3. **用出來的心得**（跑一次之後才知道的：這個工具在這個情境下要注意什麼、
   哪種輸入會讓它出錯、上次用它踩過什麼坑）——**這部分只有靠實際用過才長得出來**，
   一開始是空的，不用假裝有內容。

## 怎麼維護

- **動工前**先看自己的工具箱（不是每次都要看 `TOOLS.md` 全文——工具箱是你自己
  已經篩過、跟你有關的子集）。
- **用完之後**，如果這次用某個工具的方式值得記下來（不是每次都要），
  照 `kb-append` 同樣的精神追加——工具箱目前沒有獨立的 `board_tool.py` 子指令，
  先用 Edit 直接追加進 `toolbox/<name>.md`，標日期、簡短。
- 工具箱內容跟 `TOOLS.md` 對不上時（例如工具箱寫著某支工具、但 `TOOLS.md` 已經標
  `deprecated`），**以 `TOOLS.md` 為準**——工具箱是個人筆記，不是治理權威。
