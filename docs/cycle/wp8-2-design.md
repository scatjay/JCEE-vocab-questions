### 1. 精熟判定（政策7）操作化文字

**裁決：融合 learning-scientist-v2 的「跨場次獨立事件」定義 ＋ assessment-expert 的「n 要拉高、猜對雜訊不可忽略」＋ learning-scientist-v2 自己提出的跨站分級降級用語，寫成一條規則（見下方「修訂後政策文字」）。**

理由：
- learning-scientist（v2 與模擬版一致）指出的歧義本身是對的：「連續2次答對」沒寫死是不是同一天湊出來的，必須釘死成「各自獨立的跨天到期複習事件」。**採納**。
- assessment-expert 指出 n=2 在四選一情境下猜對機率約 6.25% 不算可忽略雜訊，建議 n=3 才對外用「精熟」字樣。**採納**——n 從 2 拉到 3，且獨立事件之間不只要求「距上次接觸 ≥7 天」，還要求「不在同一個 sessionId」，把 learning-scientist 的歧義和 assessment-expert 的雜訊疑慮一次關掉。
- 模擬版 learning-scientist 判「遷移／跨站」為**違反**（沒要求跨站測）；learning-scientist-v2 判「有疑慮」並提出「只在跨站對應題存在時才要求、否則用語降級」的方案。**採納 v2 版本、不採納模擬版的一刀切**。理由：把跨站驗證訂成所有 KC 的必要條件，會讓大量只存在單一站的 KC 永遠卡在「無法精熟」，這違反北極星「有餘裕、別讓學生卡關」的精神，也會製造大量學生怎麼練都拿不到肯定回饋的挫折感（這點 v2 已經指出，且與 game-designer「能力可見對長期動機重要」的觀察一致）。v2 的「有跨站對應題才要求、沒有則降級用語但仍記錄成就」是更精準、對兩種情境都不會錯殺的版本。

### 3. KC 鍵值混用（english-teacher 發現）

**裁決：資料層拆開兩套鍵值，但用「輕量規則」而非新增標註工程。**

english-teacher 的發現是對的且其他四份都沒提到：wordwheel 的 `t`（parse/pos/sense/infer/fake）是**答題行為分類**（學生怎麼答錯），
gsat 的 `collocation` 是**考點分類**（這題考什麼）——兩個不同維度，混用會讓歸因方向跟錯（把「他常常用詞性猜」誤判成「他這個考點沒學好」）。

**裁決不是叫工程重造一套 KC 分類法**（那需要人工標註、時程不允許），而是明確規定：
- KC 鍵值 `kcId = ${station}:${contentKey}`，`contentKey` 只能是「內容/考點」維度：
  gsat/zhikao 用該題目標單字（headword）；wordwheel 用 `DATA[].k`（字族，如 `re-`）；其餘站沿用既有題型分類或單字本身。
- `t`（及任何未來出現的「答題行為/錯誤類型」欄位）一律記為每次作答的 `errorMode` 屬性，**不進 KC 鍵值**、不影響精熟判定與排程，
  只給 AI 家教／老師報表拿來寫診斷語句用（「你常見的錯誤型態是猜字義」）。

- 採納：english-teacher 的核心發現（兩維度不可混用）。
- 未採納：她建議「需要工程/資料設計者確認 merge 邏輯」暗示的方向如果是「另立一套跨站統一的 KC 分類法」——不採納，理由是本專案各站 KC 顆粒度本來就不相通（v2 也提到這點），統一分類法的工程量遠超這輪能負擔；上面的輕量規則已經把兩個維度分開，不需要統一分類法就能解決歸因錯誤問題。

### 4. 驗收標準覆蓋缺口（政策4/6/7）＋ 政策4 vs 政策6 優先序衝突

**裁決：寫成明確算法**（assessment-expert 與 game-designer 都指出衝突但都沒給出同一套解法，這裡由 cycle-designer 合成）：

```
每日排入 N 題：
1. 到期複習集合 R = cards SRS 到期 ∪ 非卡片站簡單間隔表到期 ∪ wrongItems 未修復，
   依「逾期天數」與「missCount」排序（越逾期、miss越多，優先）。
2. 複習配額上限 = ceil(0.7×N)；新題配額上限 = floor(0.3×N)。
   頭兩週（北極星既有的「先建廣度」期）：複習配額上限降為 ceil(0.5×N)，新題配額上限提高為 ceil(0.5×N)，
   兩週後切回 70/30。
3. 若 |R| ≥ 複習配額上限：複習排滿配額上限；新題仍照新題配額上限出，
   新題保底至少 1 題（N≥2 時），複習優先權不吃掉新題保底。
4. 若 |R| < 複習配額上限：複習全部排入（|R| 題），缺口轉給新題，
   但當日新題總數（配額 + 轉入缺口）不得超過 ceil(0.5×N)——避免某天新題灌爆、
   破壞交錯與期望難度 85% 的校準。極端情況（R 與新題候選都不足以填滿 N）才允許超過此上限，
   並在資料標記 `queueFillMode:'shortage'` 供除錯與老師報表辨識。
5. 交錯規則（政策5）套用在最終排序後的整條隊列上，不是分開排 review/new 兩段再串接
   （否則會出現「前70%全複習、後30%全新題」這種違反交錯的排列）。
```

同時採納 learning-scientist-v2 的「交錯下限」建議：政策5補上「同一 KC 兩次出現之間至少間隔 3 題不同 KC」（初始值，之後依真實資料調整）。

- 採納：assessment-expert 與 game-designer 各自指出的衝突存在（雙方都對，只是都沒給解法）。
- 採納：learning-scientist-v2 指出的「驗收標準完全沒覆蓋政策4/6/7」——這是本輪最重要的補丁之一，見下方驗收清單。

### 5. 難度公式邊界行為（政策3）

**裁決：這輪只修 tie-break 與冷啟動切換點（工程可以馬上做），統計形式重新設計標記為「待下一輪跟 assessment-expert 真身對焦」，不在本輪定案。**

理由：learning-scientist 與 assessment-expert 都指出的 tie-break 問題（clamp 吃掉鑑別力）是具體、範圍小、可以立刻寫死的工程修正——採納，見下方修訂政策文字。
但 assessment-expert 指出的「θ 個人小樣本統計不穩、跟全國大樣本 d 直接線性相加不對稱」是統計模型形式的問題（要不要換成 logistic/Rasch），
這個決定會牽動排程與工程量，且**這份 assessment-expert 意見是模擬產出、非真身**，統計方法選型這種需要專業判斷準確性的建議，
我認為值得等真身 `assessment-expert` 重新審查一次再定案，不在這輪冒然決定要不要換模型。**列為待定，見下方待決事項。**

- 採納：tie-break 排序鍵改用 clamp 前的原始差值。
- 採納：冷啟動先驗的明確切換點（該生此 KC 累積作答數 ≥5 題後全面讓位給實測 θ）。
- 未採納（本輪）：是否要把整個統計形式換成 logistic/Rasch——不是不同意，是判斷本輪不該由模擬版意見驅動一個牽動時程的模型改動，需要真身審查後再排。

### 7. WP-9 UX 風險（ux-designer 發現）

逐一裁決：

- **色彩不要沿用 wrong 紅**：**現在定案**——WP-9 路由畫面改用站內既有 `--teal`（代表答對/核心的正向色），跟錯誤紅、官方橘拉開。
- **不要用彈窗**：**現在定案**——比照 wordwheel 既有「這一輪做完了」直接替換 `qstem` 文字＋清空選項的模式，不做需要主動關閉的 modal。
- **一步到位 vs 兩段式**：**現在定案**——一顆主要按鈕直接 deepLink 到選定的降階站，次要選項用文字連結列在旁邊，不要求先「了解」再選單。
- **`roots/index.html` 落地頁是否為空搜尋框**：**待人工確認**，不是這輪能關閉的問題（需要真人在瀏覽器讀完整檔案確認 `location.hash` 有沒有捲動邏輯，grep 做不到）。
  但**現在先定案要求本身**：路由連結必須帶預設篩選/錨點參數，不能是要求學生自己打字才看得到內容的空白頁——這個「要求」本輪定案，「roots 站現在到底有沒有支援」待確認。
- **重複觸發需要冷卻機制**：**採納，現在定案**——完整的「誠實告知＋降階」文案只在同一次觸底事件第一次觸發時完整播放；
  之後在冷卻窗口內（距上次觸發 <24 小時，或該生尚未在此之外連續答對 ≥5 題脫離觸底狀態）重複觸發時，只顯示簡短的降階按鈕，不重播完整文案。
- **「為什麼給你這題」呈現位置與展開/收合**：**裁決：兩者都要（呈現＋記錄），不是只記錄**。
  理由：只存 log 不呈現，會浪費領域簡報 §2「提取失敗後的解釋最有效」這個時機（learning-scientist-v2 也指出同一件事）。
  裁決細節：呈現在**作答前**（題幹旁小徽章，預設收合，點/tap才展開），不放進答題後的解析資訊堆疊（會跟 gsat 既有6層解析資訊混在一起、時間點也不同）。
  像素級細節（padding、觸控尺寸 ≥28px）留給 build 階段照 ux-designer 走查意見（`docs/cycle/wp8-2-review-ux-designer.md`）處理，這裡定案的是「必須呈現、呈現時機在作答前、預設收合」三件事。

## 修訂後的政策文字（可直接抄進規格）

**政策1／2（KC 歸因，含鍵值定義）**：
> KC 鍵值只取內容/考點維度，格式 `kcId = ${station}:${contentKey}`：
> - gsat／zhikao：`contentKey` = 該題目標單字（headword）；`collocation` 欄位若存在，記為該次作答的屬性 `hasCollocation` 與原文字串，不進鍵值本身。
> - wordwheel：`contentKey` = 該題所屬字族（`DATA[].k`，如 `re-`、`-tion / -sion`）。
> - cards／translate／class：沿用該站既有題型分類欄位；沒有的用單字本身。
> `t`（wordwheel 的 parse/pos/sense/infer/fake）與任何「答題行為/錯誤類型」欄位，一律記為每次作答的 `errorMode` 屬性，
> 不得進入 KC 鍵值、不影響精熟判定與排程；用途是給 AI 家教與老師報表寫診斷語句。

**政策3（難度targeting，修訂 tie-break 與冷啟動）**：
> 預測成功率 `p_raw = 0.5 + (θ − d)`；展示/防呆用 `p = clamp(p_raw, 0, 1)`。
> **排序鍵一律用 `p_raw`**（未 clamp 的原始差值）計算 `|p_raw − 0.85|` 最小者優先，clamp 後的 `p` 只用於對外顯示（避免呈現 >100% 或 <0% 的機率數字），不用於排序。
> 冷啟動：θ 使用該年級先驗，直到該生在此 KC 累積作答數 ≥5 題後，先驗全面讓位給實測 θ（該生近期作答的加權正確率）。

**政策4＋6（合併，到期複習優先序 vs 新舊比例衝突解法）**：
> 每日排入 N 題：
> 1. 到期複習集合 R（cards SRS 到期 ∪ 非卡片站簡單間隔表到期 ∪ wrongItems 未修復），依逾期天數與 missCount 排序。
> 2. 複習配額上限 = ceil(0.7×N)；新題配額上限 = floor(0.3×N)。頭兩週複習/新題配額各改為 ceil(0.5×N)，兩週後切回 70/30。
> 3. 若 |R| ≥ 複習配額上限：複習排滿配額上限，新題仍照配額出，新題保底至少 1 題（N≥2 時）。
> 4. 若 |R| < 複習配額上限：複習全部排入，缺口轉給新題，但當日新題總數不得超過 ceil(0.5×N)；
>    唯有 R 與新題候選都不足以填滿 N 的極端情況才允許超過，並標記 `queueFillMode:'shortage'`。
> 5. 交錯規則（政策5）套用在最終排序後的整條隊列，不是分開排兩段再串接。

**政策5（交錯，補下限）**：
> 同一 KC 連續不超過 2 題；且同一 KC 兩次出現之間至少間隔 3 題不同 KC（初始值，之後依真實資料調整）。

**政策7（精熟判定，修訂版——這是「攻克」的操作型定義，全計畫最重要的一段文字）**：
> 同一 KC 需通過 **3 次獨立的到期複習事件** 才標記精熟：
> - 每次事件必須「距上次對此 KC 的作答 ≥7 天」且「與前一次計入的正確事件不在同一個 `sessionId`」；
> - 3 次都必須答對，中間任何一次答錯，`consecutiveSpacedCorrect` 歸零重算——不是三次裡對兩次就算數；
> - 若該 KC 在多個站都有對應題目，且這 3 次中至少 1 次發生在與其他次不同的站：對外顯示「精熟」（攻克的操作型定義成立），`crossStationVerified:true`；
> - 若該 KC 只存在單一站，或雖存在多站但這 3 次都發生在同一站：內部照樣記 `masteredAt`（排程照樣拉長到最長間隔），但對外顯示降級為「此站已穩定」，並在老師報表/AI家教注記「僅單站驗證，遷移未測」，`crossStationVerified:false`。
> - 「攻克」一詞只能在 `crossStationVerified:true` 時使用；`crossStationVerified:false` 一律用「此站已穩定」。
> - 🔴 **在 Phase 0 資料層補丁通過驗收前，「攻克」「精熟」兩詞禁止出現在任何使用者可見畫面。**

**政策8（為什麼給你這題，補呈現規則）**：

### 裁決：(c) 維持現行線性公式 `p_raw=0.5+(θ−d)`，不換 logistic/Rasch，附具體重新評估觸發訊號

**採納 assessment-expert 真身複審的結論與理由，逐條記錄**：

1. **換 logistic 能解決的問題，跟真正的問題是兩個獨立問題**：logistic/Rasch 能讓輸出天然落在
   `[0,1]`，但不解決「θ（該生此 KC 的個人近期正確率，樣本數常是個位數，雜訊大）跟 d（全國大樣本
   官方答對率，穩）直接線性相加」這個訊噪不對稱問題——這兩個問題在模擬版 `assessment-expert`
   （`docs/cycle/wp8-2-review-assessment-expert.md`）的意見裡被混在一起講，真身複審把它們拆開，
   結論是換曲線形狀對第二個問題沒有幫助，換了模型訊噪不對稱依然存在。
2. **公式失真最嚴重的區域，跟選題排序實際會用到的區域，理論上互斥**：clamp 造成的失真在
   `|θ−d|>0.5`（θ 與 d 差距很大）時最明顯；但選題排序鎖定的是 `|p_raw−0.85|` 最小的候選，也就是
   `θ−d≈0.35` 附近——這兩個區域大致不重疊，所以 clamp 失真對「決策相關」的實際選題範圍影響可忽略。
   **這是理論推導，未經真實資料驗證**——本專案目前沒有真實學生資料可以驗證這個互斥假設是否成立，
   這是本裁決保留的一個已知風險，見下方「重新評估觸發條件」。
3. **已生效的 tie-break 修正已經解決本輪唯一真正會被使用者感受到的問題**：排序鍵改用 clamp 前的
   `p_raw`（`docs/PLAN.md` §5 政策5 既有裁決）已經處理掉「θ 與 d 差距大時多個候選同分、tie-break
   退化成任意選」這個真正會影響學生實際拿到什麼題目的問題；換模型不會讓這個已解決的問題變得更好。
4. **換模型違反本專案「一句話解釋得完」的紅線**：logistic/Rasch 的「一句話解釋」草稿本身就比
   `p_raw=0.5+(θ−d)` 更難懂，這跟政策3、政策8 mutation 提案被否決是同一個理由（`docs/PLAN.md` §5
   政策5「公式要能用一句話解釋」、`docs/cycle/MUTATIONS.md` #1 對方案B的否決）。且「真的 Rasch」
   模型需要校準資料，本專案目前 **0 個真實學生資料**，校準不了——不是「換了會更準」，是「換了也校不出來，
