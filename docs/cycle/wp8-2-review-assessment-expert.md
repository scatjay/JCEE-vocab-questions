# WP-8 教學決策層 — assessment-expert 審查

> 產出方式：本輪因 session 限制，用 `general-purpose` 注入 `assessment-expert.md` 人設模擬產出，
> 不是真正註冊的 subagent_type 執行。新 session 用真正類型重跑一次驗證一致性。
> 產出時間：2026-09-14 00:16

## 目前系統宣稱了什麼

1. 「精熟」：同一 KC 間隔 ≥7 天再測**連續 2 次**答對 → 標記精熟
2. 「攻克」：北極星把「攻克」的操作型定義綁在上述精熟判定
3. 難度targeting：`p = clamp(0.5+(θ−d))` 號稱「預測成功率」，選 `|p−0.85|` 最小的題
4. 官方答對率作為難度基準 `d = 1−答對率`
5. （隱含）系統具備「隔期再測」的資料能力——這是北極星與精熟判定的前提

## 逐條判定

- **[要改措辭] 精熟（n=2 就標記）**：四選一題型猜對base rate 25%，連續 2 次猜對機率約 6.25%，不是可忽略的雜訊。且規格沒說 re-test 是同一題還是同 KC 不同題——若同一題，測到的是**題目記憶**不是 KC 遷移。
  → 可用說法：n=2 先標「初步穩定」，n=3 才升級為對外顯示的「精熟」；或保留 n=2 但資料與報表都存「信心層級」而非二元旗標。

- **[不能講] 「攻克」＝精熟判定達成**：地基（精熟定義）本身站不住，加上**資料模型目前沒有任何欄位能重建「這個 KC 何時第一次答對、何時再測、結果為何」的序列**——連判定用的原始事實都存不下來。
  → 北極星目標留著沒問題（是設計方向），但「攻克」這個詞在 WP-1 資料層補齊前，**一律不能出現在任何使用者可見的畫面或報表上**。

- **[要改措辭] 難度targeting「預測成功率85%」**：公式一句話解釋得完，滿足專案門檻。但 `d`（官方答對率，全國大樣本，穩）與 `θ`（個人近期正確率，通常樣本數個位數，很不穩）用同一條線性加法直接相加，一個精準統計量被一個雜訊很大的統計量拖著走。且沒看到 θ 何時從先驗過渡到個人值的機制。
  → 可用說法：對內部/老師講「系統估計」，對學生端不要出現具體百分比，只用來排序不要當精確度量展示。

- **[撐得住] 官方答對率當難度基準 `d`**：本專案獨有且合理的資產，全體考生樣本、穩定，繼續用。

- **[不能講] 「系統具備隔期再測能力」**：這是本次審查主要發現——`progress`／`sessions`／`wrongItems` 三張表沒有一張能支撐。

## 要補什麼資料才撐得起原本想講的話

現況：
- `progress.stations/{stationId}` 只有站層級累計，沒有 KC 維度、沒有時間序列。
- `sessions` 每筆只記總數，沒記是哪些題目/KC，事後無法反推「這個 KC 這次 session 對不對」。
- `wrongItems` 只有答錯過的題目才出現，`repairedAt` 是單一值不是序列，答對從不被記錄成事件。

拿現有三張表回答「同一KC間隔≥7天再測連續2次答對」**答不出來**：從未答錯的題目完全沒有逐次記錄；`repairedAt`無法判斷連續2次；沒有以KC為鍵值的彙總節點；θ在現有模型下無法計算。

**具體建議**：
- 新增 `progress/{uid}/kc/{kcId}: { attempted, correct, recentWindow:[{at,correct,itemId}]（上限如10筆）, consecutiveSpacedCorrect, lastTestedAt, masteredAt }`——這是θ計算與精熟判定唯一站得住腳的落點。
- 答對也要留痕，不要只有錯題才留痕。
- `wrongItems.repairedAt` 改成小型歷史（陣列/子節點），否則「修好後又錯」會被系統當沒發生過。
- 明確定義 re-test 的單位：同一題重出 vs 同KC換題？這是效度問題（測的是題目記憶還是KC遷移），要先決定，schema才知道該用itemId還是kcId當比對鍵。

## 給老師報表的標註建議

- 「精熟」/「攻克」字樣旁必須標**觀察次數**與**資料期間**，不要只顯示綠色勾勾。
- 難度targeting選出的題目若顯示給老師，標「系統估計難度」而非「官方難度」。
- `progress`已知可被學生端竄改，報表引用精熟/KC統計優先源頭應是未來append-only節點，不要直接讀可被竄改的節點。
- 樣本數過小的KC（1-2次）應明確標「資料不足，尚無法判斷」，不要因沒資料顯示0%或空白，會被誤讀成0分。

## 交給誰

- 難度公式要不要換成logit/類Rasch形式修正線性混合大小樣本統計量的問題 → `learning-scientist`（並經`cycle-designer`裁決是否仍符合「一句話解釋完」門檻）
- re-test算同一題還是同KC，牽動KC分類邊界怎麼定義 → 領域模型/教學決策設計角色
- WP-9「最近20題正確率」滾動視窗跟本審查發現的「無逐次時間序列」是同一根源缺口 → `red-team-critic`主審時一併注意
- 效度 vs 工程成本的取捨 → builder或`cycle-designer`
