## 逐條判定

- **[合格] 知識成分歸因**（政策1、2）：`d`（難度）優先用大考中心官方答對率、`θ`（能力）用該 KC 加權近期正確率，兩者都掛在 KC 這個顆粒度上、KC 來源沿用原站既有欄位（`accuracyRate` 等），沒有另外人工標註。符合領域簡報 §1 的資產定位與判準1的核心要求。
  → 小補充（不影響合格判定）：原站 gsat 站還有 `discrimination`（鑑別度）欄位，政策1目前只用 `accuracyRate` 沒用到它。鑑別度低的題目即使答對率落在期望難度區間，也可能是「猜對」而非「真的懂」，這個訊號目前被丟棄了。是否要用、怎麼用，屬於 `assessment-expert` 的心理計量範圍，我只標記「這個現成資產還沒被用上」。

- **[不適用/合格] 檢索優先**：WP-8 管的是「下一題給什麼、什麼時候到期複習」的選題政策，不是站內「先答再看解析」的作答流程（那是各站引擎既有行為，WP-8 沒有動它）。沒有發現 WP-8 把解析提前呈現的設計。維持不適用判定。
  → 但有一處邊界值得指出（見政策8條目）：政策8存的「為什麼給你這題」理由，若只給老師報表/AI家教看、不在答錯當下呈現給學生本人，就錯過了領域簡報 §2「提取失敗後的解釋最有效」這個時機。這不是「檢索優先」被違反，而是一個被浪費掉的資產，寫在政策8底下。

- **[合格] 交錯**：政策5「同一 KC 連續不超過 2 題」直接對應領域簡報 §2 的交錯原則，驗收標準也有機械化檢查（任取連續10題檢查）。
  → 有疑慮但不影響合格：這條規則只設了「上限」（連續不超過2題），沒有設「下限」（同一 KC 下次出現前至少要隔幾題）。技術上「KC-A, KC-A, KC-B, KC-A, KC-A, KC-B...」也符合「不超過2題連續」，但實質上仍接近集中練習（massed practice）的變體，不是真正的交錯。
  → 建議：驗收標準除了「連續不超過2題」，再加一條「同一 KC 兩次出現之間至少間隔 N 題不同 KC」（N 可以先設 3–5，之後用真實資料調），一起機械化檢查。

- **[有疑慮] 間隔——精熟判定的操作化文字有歧義**（政策7）：規格寫「同一 KC 在間隔 ≥7 天後再測連續 2 次答對 → 標記精熟」。這句話至少有兩種讀法：
  (a) 兩次「跨天的到期複習事件」都各自答對（真正跨時間驗證兩次）；
  (b) 某一次到期複習出現時，因為 UI 設計連續給了 2 題同 KC，這次「連續2題都對」就算數（可能發生在同一天、同一 session）。
  規格沒有寫死是哪一種，工程師照字面最省事的實作方式很可能落在 (b)，而 (b) 沒有真正檢驗「跨時間保留」，只驗證了「這次還記得」，牴觸北極星結論3「攻克＝隔期再測仍答對，不是曾經答對一次」。
  → 建議：把規格改寫成清楚可執行的版本——「該 KC 必須通過至少 2 次各自獨立的到期複習事件（每次事件本身都在距上次接觸 ≥7 天後出現），且每次都答對，才標記精熟」。同時要在**驗收標準**裡補一條機械化檢查（見下一條，這是目前規格最大的漏洞）。

- **[違反] 驗收標準沒有覆蓋政策4、6、7**：PLAN.md §5 WP-8 目前列出的4條驗收，分別對應到政策1/3（難度分布）、政策5（交錯）、政策8（理由一致）、以及負面案例（觸底）。**到期複習排程是否真的優先於新題（政策4）、新舊比例是否落在 30/70 附近（政策6）、精熟判定是否真的要求跨場次（政策7）——這三條完全沒有對應的機械化驗收**。政策7正是「攻克」這個操作型定義的地基，卻是驗收覆蓋最薄弱的一條，就算規格文字寫清楚了，沒有驗收去逼它，實作偏差也不會被抓到。
  → 建議：至少補三條驗收——
  ① 造一個「同一天故意把同 KC 的到期複習題連刷 2 次」的假學生，驗證系統**不會**因此標記精熟（直接檢驗政策7的歧義是否被正確消解）；
  ② 造一個到期複習題數本身就超過70%配額的假學生，觀察當日出題是否仍照規格處理新舊比例（直接檢驗政策4/6的優先序衝突有沒有寫死行為）；
  ③ 追蹤一個假學生連續30天的出題記錄，統計新題/複習題比例是否落在30/70附近（±合理誤差）。

- **[有疑慮] 期望難度公式的邊界行為**（政策3）：`p = clamp(0.5 + (θ − d))`，選 `|p − 0.85|` 最小的候選。公式本身符合「一句話解釋得完」的紅線，合格。但兩個實務疑慮：
  1. 線性近似會被 `clamp` 吃掉鑑別力——當 θ 與 d 差距夠大時，多個候選的 p 會同時撞頂（1.0）或撞底（0.0），這些候選在 `|p−0.85|` 上完全平手，選題會退化成任意選（實際上退到「隨機選一個過難或過易的題目」，恰好是期望難度原則要避免的情況）。規格沒講平手時怎麼排序。
     → 建議：排序鍵改用「clamp 前的原始差值 `0.5+(θ−d)`」做 tie-break，clamp 只留給呈現/防呆用，不要用在排序上。
  2. 冷啟動 θ 用「該年級先驗」，規格沒寫先驗維持多久、何時切到實測值。若先驗期拖太久，等於全班共用同一份難度分布，違背「這個學生」的個人化承諾。
     → 建議：明訂切換點，例如「該生在此 KC 累積作答數 ≥5 題後，先驗全面讓位給實測 θ」，並在驗收標準裡加一筆檢查。
  （線性近似該不該換成 logistic/Rasch 模型——超出我的判準，交給 `assessment-expert`。）

- **[有疑慮] 新舊比例（政策6）與「到期複習優先」（政策4）的優先序衝突**：兩條規則在邊界情況會打架——當日到期複習題數本身超過70%配額時，新題要不要照樣塞進30%？到期複習不到70%時，缺口要不要用新題補滿？規格沒寫清楚，等於把決定權留給實作者，而不同實作者會做出不可預測、且互不一致的行為（這對「同一個系統給不同學生的體驗要一致」是隱性風險）。
  → 建議：寫成明確算法，例如「當日題數 N：先填滿到期複習（上限 0.7N）；到期不足 0.7N 時，剩餘配額全給新題，但新題保底仍不得超過某上限（避免某天突然塞爆新題破壞交錯與難度校準）」。這個具體算法本身該由工程實作者定，但**規格層必須先寫死優先序**，不能留白。

- **[不適用] 回饋時機與內容**：WP-8 本身未觸及站內回饋機制（各站引擎既有行為），未發現違反。已在「檢索優先」條目下指出一個相關但不同的問題：政策8生成的「為什麼給你這題」理由，若不在答錯當下呈現給學生，就浪費了領域簡報 §2「提取失敗後的解釋最有效」這個時機。**這個建議的落點是 WP-5（AI家教）或站內 UI，不是 WP-8 本身該解決**，但 WP-8 產生的資料是這件事能不能發生的前提，所以在此標記提醒。

- **[有疑慮，不同意模擬版的「違反」] 遷移**：模擬版判定政策7「違反」遷移原則，理由是精熟判定沒有要求換站/換題型再測。我讀規格與領域簡報後，判定強度改為「有疑慮」而非「違反」，理由是：
  各站 KC 的顆粒度與標籤框架本來就不完全相通（gsat 的 collocation/note、wordwheel 的 t=parse/pos/sense/infer/fake、原站五詞框架），並非每個 KC 都天然存在「同一個 KC 換一個站也能測」的對應題目。如果把「跨站驗證」訂成精熟判定的**必要條件**，會讓大量只存在單一站的 KC 永遠卡在「無法精熟」，這反而違背北極星「有餘裕、別讓學生卡關」的精神，也可能製造一個學生怎麼練都拿不到「精熟」標記的挫折感（動機層問題，交給 `game-designer` 評估，但源頭在這裡的規則設計）。
  但模擬版指出的核心風險是對的：**當跨站對應題確實存在時，規格完全沒有要求用它**，這樣「精熟」的宣稱品質會不一致（有的 KC 真的跨站驗證過，有的只在單一站驗證過，但對外呈現一模一樣都叫「精熟」），這對老師和學生是誤導。
  → 建議（比模擬版更保守、更可執行的版本）：只在「該 KC 於多個站都有對應題目」時，才要求兩次跨天答對中至少一次來自不同站；若該 KC 只存在單一站，維持現行判定但**對外呈現要降級用語**（例如「此站已穩定」而非「精熟」），並在老師報表與 AI 家教建議卡裡注記「僅單站驗證、遷移未測」。這樣不會把單站 KC 判死，但也不會讓「精熟」這個詞在不同驗證強度下被同等使用。

## 最重要的一件事

如果只能改一項：**把政策7（精熟判定）的規格文字釘死成「兩次獨立的跨天到期複習事件」，並且在 WP-8 的驗收標準裡新增一條機械化檢查**——造一個「同一天故意連刷2次同KC」的假學生，驗證系統不會因此判定精熟。目前這條規則不只是文字模糊（前面已指出），連驗收標準都完全沒有涵蓋它，等於「攻克」這個貫穿整份計畫（北極星結論3、§6已定案決策）的操作型定義，是全計畫裡驗證最薄弱的一環。規格模糊+沒有驗收=就算工程師老實照做，也沒有任何機制能發現他做錯了。

## 這超出我的範圍、應該問誰

- θ 的心理計量估計方法（加權近期正確率的權重怎麼定）、線性近似是否該換成 logistic/Rasch 模型、discrimination 欄位要不要納入難度計算 → `assessment-expert`
- 30/70 比例衝突、單站精熟降級用語，對學生動機與「感覺被信任/被公平對待」的影響 → `game-designer`
- WP-9 底線偵測訊息、以及本審查提到的降級用語（「此站已穩定」）對低閱讀能力學生是否讀得懂、會不會被誤解成負面評價 → `english-teacher`、`red-team-critic`
- 政策8「為什麼給你這題」理由該不該在答錯當下直接呈現給學生（而不只是給老師/AI家教看）——這是 WP-8 與 WP-5、站內 UI 的介面問題，我只指出時機，不做介面設計 → 負責 WP-5 的角色與 `ux-designer`
