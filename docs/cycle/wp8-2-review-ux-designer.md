## 我走過的流程

WP-8/WP-9 都還沒有任何畫面（`game/engine.css` 不存在、`wordwheel.html` 也還沒 import `engine.js`），所以走的是這兩個功能將來會插進去的既有流程，用既有畫面結構倒推新元件該插在哪裡。

**wordwheel.html 現有作答流程**（L212–296）：看輪子→點「考自己」（0秒延遲出第一題，無額外設定畫面）→點選項→立即上色 right/wrong→同時顯示`.after`(why)+`.wtags`+比分→「下一題」→做完後**直接把`qstem`換成結算文字、清空選項、顯示「再做一次」**——這個既有模式正是 WP-9 誠實路由畫面最省事、最一致的落地方式。

## 逐條判定

### (a) WP-9 誠實路由畫面

- **[有問題] 語氣中性度**：wordwheel 把「錯」跟警示色死死綁定（`.opts button.wrong{background:#fdeceb;border-color:#c0554a}`）。學生連續看到多題紅色 wrong 後，若路由畫面沿用同組紅/橘，會被讀成「第9個懲罰」。
  → 改用 `--teal`（wordwheel裡代表答對/核心的正向色）當主色，跟錯誤紅、官方橘拉開。

- **[有問題] 呈現形式**：PLAN沒說是覆蓋題卡、彈窗、還是banner。彈窗需要「X」關掉，對挫折學生是額外心理成本。
  → 比照wordwheel既有「這一輪做完了」結算模式，直接換`qstem`文字+清空選項+按鈕改「去看看字根家族表」，不要用需要主動關閉的modal。

- **[有問題] 一步到位 vs 兩段式**：若先「了解」再顯示選單再選，等於挫折學生要點2次。
  → 直接一顆主要按鈕deepLink到選定的降階站，次要選項用文字連結列在旁邊。

- **[待驗證，列風險] 落地頁是不是空殼**：`roots/index.html`首次進入是空搜尋框（L74-78），245個字要學生自己打字才看得到。因挫折被轉介的學生落地看到空搜尋框，會覺得「這個逃生門也沒有用」。
  → 路由連結要給帶預設篩選或第一個字根家族錨點的網址，不是要求「自己打字找」。**未確認**：`roots/index.html`是否有讀取`location.hash`並捲動的邏輯，只看到nav產生錨點的程式碼，需人工確認完整檔案。

- **[有問題] 重複觸發風險**：偵測窗「最近20題」，學生被路由後若按上一頁回原站，下一題答錯視窗幾乎沒變，可能立刻再觸發。連續被同一句話擋兩次比一次更糟。
  → 需要冷卻機制（同session不重複觸發，或距上次觸發過一段時間/答對幾題才重新評估）。**PLAN目前沒寫，需補進WP-9驗收標準**。

- **[有問題] 「不假裝」與「不放棄他」的拉扯**：PLAN只規定訊息不能含哪些詞，沒規定要含什麼才不會讀成「系統放棄我」。
  → 文案怎麼寫超出我的範圍，但介面上確定：訊息旁一定要有一個具體、點得下去的動作同框出現。

### (b) WP-8「為什麼給你這題」

- **[有問題] 放置位置會跟gsat既有資訊層級打架**：gsat已有6層說明疊著。若塞進`#qExplain`變第7層，且它回答的是「作答前」問題，跟其餘6層「作答後」問題時間點不同卻放同一位置，學生分不清。
  → 放在答題前、`#qTag`同一行，用小徽章呈現，不要放進答題後的說明堆疊。

- **[有問題] wordwheel對應位置混淆風險**：若用敘述式文字呈現，跟`.after`(why，也是敘述式)風格一樣，學生會搞混「為什麼給你這題」跟「這題為什麼是這個答案」。
  → 比照`.qhint`既有徽章做法（小、單行、非敘述句），或用`roots/index.html`已有的`<details><summary>`收合模式（已證明此站可行、有鍵盤可及樣式）——預設收合成一行極短徽章，點/tap才展開。

- **[有問題] 「每題都要帶」是要顯示還是只要記錄，PLAN沒說清楚**：WP-8條8「存進資料」跟這次交辦的「介面怎麼呈現」，兩者對「帶出」的解讀不一致。
  → 若要顯示，必須用預設收合，否則拖慢WP-4番茄鐘的~25秒/題節奏；若只存log，介面完全不用做事。**這個歧義建議退回cycle-designer裁決**。

- **[有問題] 觸控目標大小**：若做成可展開徽章，wordwheel現有徽章padding只有`.06rem .4rem`，是閱讀用尺寸不是點按用尺寸，且跟旁邊不能點的徽章長一樣，affordance不足。
  → 加大padding到至少28px高，或用明顯圖示/虛線底線標出可點開。
